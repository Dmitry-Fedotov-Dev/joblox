# Joblox Network

Биржа исполнителей и общий счётчик на https://joblox.openline.one. Клиент открывает биржу как приложение:
сверху «Заказать такси», ниже «Сделать доставку», выпечка, перевозки, магазины. В каждом разделе карточки
исполнителей, у которых программа включена прямо сейчас. Внизу большая кнопка «Стать исполнителем» с выбором
роли: водитель, курьер, пекарня у дома, перевозчик, продавец. Рядом стоят проекты OpenLine (Радио, Agent Pay).

Каждый исполнитель работает сам: программа запущена на его телефоне или компьютере, заказы и деньги идут
напрямую к нему. Биржа только показывает ссылки и счётчики, она не принимает заказы и деньги.

## Как установка попадает на биржу

`joblox up` (запуск у себя, см. README) включает сеть сам: `JOBLOX_NETWORK_URL=https://joblox.openline.one`.
Сервер, настроенный вручную (`joblox serve`), участвует, только если задать эту переменную.

Раз в 5 минут установка отправляет одно сообщение:

```json
{"id": "a3f1…(32 символа)", "kind": "taxi", "version": "1.0.0", "online": 7, "orders_today": 3,
 "listing": {"title": "Такси Азамат", "place": "Чолпон-Ата", "about": "Camry, аэропорт",
             "contact": "+996 700 000 000", "url": "https://….trycloudflare.com"}}
```

- `id` случайный, создаётся при первом включении и хранится в базе установки.
- `kind` берётся из `business.kind` профиля. Всё, кроме латиницы, цифр, `_` и `-`, сеть превращает в `other`.
- `online` и `orders_today` берутся из тех же счётчиков, что на встроенном дашборде.
- `listing` есть, только если владелец отметил «Показать на бирже» в кабинете. Это то, что он сам вписал, и
  текущий адрес его сайта. Временный адрес trycloudflare.com меняется после перезапуска, и карточка
  обновляется сама: после подключения туннеля установка сообщает новый адрес в течение минуты.

Заказы, клиенты, цены и платежи в сеть не отправляются. Выйти из сети: `JOBLOX_NETWORK_URL=off` в
`joblox.env`. Через 15 минут установка пропадёт из счётчика и с биржи, через 7 дней запись удалится.

## Открытое API

| Запрос | Ответ |
|---|---|
| `GET /api/v1/market` | `{"cards": [...]}`: исполнители на связи (сначала самые занятые) и проекты OpenLine, с CORS. `?kind=taxi` фильтрует |
| `GET /api/v1/stats` | `{"installations", "online", "orders_today", "kinds", "updated_at"}`, с CORS для любого сайта |
| `POST /api/v1/beat` | `204`, если принято; `400` при неверных полях (лишние поля тоже ошибка); `429` чаще раза в минуту |
| `POST /api/v1/hide` | Модерация: `{"id": "...", "hidden": true}` с `Authorization: Bearer <JOBLOX_HUB_ADMIN_TOKEN>` |
| `GET /`, `/start`, `/terms`, `/api` | Биржа, «Стать исполнителем», пользовательское соглашение, описание API. Без скриптов |

Карточка с неверным адресом (не `https://`) отбрасывается, счётчик при этом засчитывается. Поля режутся по
длине: название 60, место 40, описание 160, контакт 40 символов. На странице всё выводится как текст.
От адреса сайта остаётся только `https://хост/`, путь и параметры отбрасываются.

Установка считается работающей 15 минут после последнего сообщения. Вклад одной установки ограничен:
не больше 100 000 онлайн и 10 000 000 заказов. С одного адреса принимается не больше 20 новых `id` в час.
Адрес отправителя нужен только для этого лимита, держится в памяти и не записывается.

## Модерация

Владелец сети скрывает карточку по её `id` (установка продолжает считаться, но на бирже её больше нет):

```bash
curl -X POST https://joblox.openline.one/api/v1/hide -H "Authorization: Bearer $JOBLOX_HUB_ADMIN_TOKEN" \
  -d '{"id": "a3f1…", "hidden": true}'
```

`JOBLOX_HUB_CONTACT` выводится внизу страниц как «Пожаловаться на карточку».

## Свой сервер сети

Сервер сети открытый: `joblox hub` из того же бинарника.

```bash
JOBLOX_HUB_ADDR=127.0.0.1:8099 JOBLOX_HUB_DB=data/hub.db ./bin/joblox hub
docker compose -f deploy/hub/docker-compose.yml up -d --build   # или в Docker; секреты в deploy/hub/.env
```

HTTPS даёт Caddy (пример в `deploy/hub/docker-compose.yml`). Журнал Caddy для сети лучше выключить, чтобы не
хранить адреса установок.
