# Профиль бизнеса

Профиль описывает один бизнес целиком. Файл читается строго: неизвестный ключ считается ошибкой, чтобы опечатка
не изменила порядок работы незаметно. Проверить профиль: `joblox check profiles/my.yaml`.

Начните с готового профиля из `profiles/` и меняйте его под себя.

## business

| Ключ | Что это |
|---|---|
| `name` | Название, видно в шапке, письмах и боте |
| `kind` | Свободное слово для себя: shop, bakery, taxi |
| `description` | Одна-две фразы под названием на витрине |
| `currency` | Код валюты: RUB, KGS, KZT, USD, EUR. По умолчанию RUB |
| `timezone` | Часовой пояс бизнеса, например Europe/Moscow |
| `contact` | Телефон, адрес или почта в шапке и на странице отказа |

## catalog

Список позиций для профилей с ценой по каталогу.

```yaml
catalog:
  - {id: baton, title: Батон нарезной, price: 89, unit: шт, max_qty: 20}
  - {id: pie, title: Пирог с капустой, description: 800 г, price: 650, unit: шт, max_qty: 5, hidden: false}
```

`id`: латинские строчные буквы, цифры и `_`. `price`: число или строка с копейками (`89.50`). `max_qty`:
сколько можно заказать за раз (по умолчанию 99). `hidden: true` убирает позицию с витрины, не трогая старые заказы.

## pricing

```yaml
pricing:
  mode: catalog            # catalog: сумма корзины и сборов; quote: цену называет оператор
  min_total: 200           # минимальная сумма заказа
  max_total: 0             # 0: без ограничения
  fees:
    - {id: courier, title: Доставка курьером, amount: 350, free_from: 5000, when: delivery=Курьером}
    - {id: distance, title: Расстояние, per_field: distance_km, rate: 28}
```

Сбор бывает фиксированным (`amount`) или за единицу числового поля (`per_field` и `rate`: километры, килограммы,
часы). `free_from` отменяет сбор, если сумма корзины не меньше указанной. `when: поле=значение` включает сбор
только при этом ответе клиента.

В режиме `quote` корзины нет: клиент отправляет заявку, оператор называет цену командой `/price` в боте.

## checkout

Поля формы заказа. Поле `email` обязательно: на него приходят код подтверждения и статусы.

```yaml
checkout:
  fields:
    - {id: name, label: Имя, type: text, required: true, max_len: 80}
    - {id: email, label: Email, type: email, required: true}
    - {id: weight_kg, label: Вес, type: number, required: true, min: 0.1, max: 30, unit: кг}
    - {id: delivery, label: Получение, type: select, required: true, options: [Курьером, Самовывоз]}
```

| type | Проверка |
|---|---|
| `text`, `textarea` | Длина (`max_len`, по умолчанию 200 и 1000 символов), управляющие символы удаляются |
| `email` | Адрес почты, хранится в нижнем регистре |
| `phone` | Цифры, пробелы, скобки, дефисы, от 6 до 23 символов |
| `number` | Число в пределах `min` и `max` |
| `datetime` | Дата и время из календаря браузера |
| `select` | Только один из `options` |
| `url` | Только ссылка `https://` |

`hint`: подсказка под полем. `unit`: единица рядом с подписью и в карточке оператора.

## payment

```yaml
payment:
  methods: [transfer, cash]    # transfer: перевод по реквизитам; cash: при получении
  require_email_code: true     # без кода реквизиты не показываются
  reference_prefix: KL         # номер для назначения платежа: KL-1042
  window_hours: 4              # неоплаченный заказ закрывается через столько часов
```

Реквизиты хранятся в отдельном файле (`JOBLOX_REQUISITES`), а не в профиле: профиль можно держать в открытом
репозитории, реквизиты нет. Пример: [`deploy/requisites.example.yaml`](../deploy/requisites.example.yaml).
Шаблон назначения платежа обязан содержать `{ref}`, иначе оплату нельзя сопоставить с заказом.

## workflow

Статусы и переходы. Профиль проверяется при загрузке: каждый статус должен быть достижим, переход не может
начинаться в конечном статусе, все ссылки должны вести на существующие статусы.

```yaml
workflow:
  initial: new
  states:
    - {id: new, title: Новый, customer: "Заказ получен, ждёт подтверждения"}
    - {id: done, title: Выдан, customer: "Заказ выдан", final: true}
  transitions:
    - {id: accept, title: Принять, from: new, to: accepted, by: operator, requires: [approved], notify: true}
    - {id: cancel, title: Отменить, from: [new, accepted], to: cancelled, by: [customer, operator]}
    - {id: expire, title: Истёк срок, from: new, to: expired, by: system}
```

| Ключ | Что это |
|---|---|
| `title` у статуса | Название для оператора |
| `customer` у статуса | Что клиент читает на странице заказа и в письме |
| `by` | Кто может сделать переход: `customer`, `operator`, `system` |
| `requires` | Условия: `paid` (оператор отметил оплату), `approved` (антифрод пропустил или оператор одобрил), `priced` (цена известна), `verified` (клиент подтвердил email) |
| `notify` | Отправить клиенту письмо о новом статусе |

Флаги ставят только действия оператора вне графа: «Оплата получена», «Одобрить», `/price`. Поэтому ни один
профиль не может дать клиенту отметить заказ оплаченным.

Системный переход из статуса в конечный статус без условий служит таймаутом: раз в минуту сервер закрывает
неоплаченные заказы, которые пролежали в этом статусе дольше `payment.window_hours`.

## antifraud

```yaml
antifraud:
  max_orders_per_ip_hour: 5        # больше: отказ
  max_orders_per_email_day: 10     # больше: отказ
  max_open_unpaid_per_email: 2     # открытых неоплаченных заказов на одну почту
  new_customer_review_above: 3000  # первый заказ дороже: ручная проверка
  review_above: 0                  # любой заказ дороже: ручная проверка (0: выключено)
  min_fill_seconds: 3              # форма заполнена быстрее: ручная проверка
  block_disposable_email: false    # одноразовые ящики: отказ (иначе ручная проверка)
  review_all: false                # проверять вручную каждый заказ
```

Подробно о правилах: [ANTIFRAUD.md](ANTIFRAUD.md).
